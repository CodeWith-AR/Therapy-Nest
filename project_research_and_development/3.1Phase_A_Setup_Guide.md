## Step 1: Set Up Supabase (Database, Auth, Storage)

Supabase is the open-source backend-as-a-service that handles your user authentication, database, and file storage.

### 1.1 Sign Up and Create a Project
1. Go to [https://supabase.com](https://supabase.com).
2. Click **Start your project** or **Sign In** in the top right.
3. Sign up using your **GitHub account** (recommended) or your email address.
4. Once logged in to the dashboard, click the **New Project** button.
5. Select your organization (or create a default one).
6. Fill in the project details:
   - **Name:** `therapy-nest`
   - **Database Password:** Click **Generate a password** (Write this password down somewhere safe! You will need it if you ever connect to the database directly).
   - **Region:** Choose a region close to Pakistan (e.g., **Singapore / ap-southeast-1**).
   - **Pricing Plan:** Select **Free** tier.
7. Click **Create new project**. It will take 1-3 minutes for Supabase to provision your database.

---

### 1.2 Get Your API Keys and Project URL
Once the project is ready, you will see your project dashboard.
1. In the left navigation menu, click the **Project Settings** (gear icon ⚙️) at the bottom.
2. Select **API** from the settings list.
3. Locate and copy the following values to a secure text file on your computer (e.g., named `.env`):
   - **Project URL** (looks like: `https://xxxxxxxxxxxx.supabase.co`)
   - **Project API anon key** (looks like a long string of letters starting with `eyJh...`)
   - **Project API service_role key** (starts with `eyJh...` — **Keep this secret!** Do not share it or put it in client-side mobile code. It is for backend use only).

### 1.3 Run the Database Schema
Now we will create the tables needed for your application.
1. In the left navigation menu, click the **SQL Editor** icon (looks like a terminal window with `SQL` inside it `[SQL]`).
2. Click **New query** (or the **+** button) to open a blank editor tab.
3. Copy and paste the entire SQL block below into the editor:

```sql
-- Enable UUID extension
CREATE EXTENSION IF NOT EXISTS "pgcrypto";

-- 1. User profiles (mirrors Supabase Auth)
CREATE TABLE user_profiles (
    id UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
    role VARCHAR(20) NOT NULL DEFAULT 'patient' CHECK (role IN ('patient','clinician','caregiver','admin')),
    full_name VARCHAR(255),
    locale VARCHAR(10) DEFAULT 'en-US',
    created_at TIMESTAMPTZ DEFAULT NOW(),
    last_login_at TIMESTAMPTZ
);

-- 2. Patient profiles
CREATE TABLE patient_profiles (
    user_id UUID PRIMARY KEY REFERENCES user_profiles(id) ON DELETE CASCADE,
    conditions TEXT[] DEFAULT '{}',
    severity_map JSONB DEFAULT '{}',
    goals TEXT[] DEFAULT '{}',
    sessions_per_week INT DEFAULT 3,
    minutes_per_session INT DEFAULT 20,
    dominant_language VARCHAR(10) DEFAULT 'en-US',
    consent_research BOOLEAN DEFAULT FALSE,
    consent_data_sharing BOOLEAN DEFAULT FALSE,
    onboarding_completed_at TIMESTAMPTZ
);

-- 3. Domains
CREATE TABLE domains (
    id SERIAL PRIMARY KEY,
    code VARCHAR(30) UNIQUE NOT NULL,
    name VARCHAR(100) NOT NULL,
    description TEXT,
    icon_name VARCHAR(50)
);

-- Insert Default Therapy Domains

('comprehension', 'Auditory Comprehension', 'Understanding spoken language', 'hearing'),
('memory', 'Memory', 'Working, short-term, and visual memory', 'memory'),
('attention', 'Attention', 'Sustained, selective, and divided attention', 'center_focus_strong'),
('speech', 'Speech', 'Articulation, repetition, and oral expression', 'record_voice_over'),
('reading', 'Reading & Writing', 'Reading comprehension and spelling', 'auto_stories'),

ON CONFLICT (code) DO NOTHING;

-- 4. Exercise items (content library)
CREATE TABLE exercise_items (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    exercise_type_code VARCHAR(50) NOT NULL,
    domain_code VARCHAR(30) NOT NULL REFERENCES domains(code),
    difficulty NUMERIC(5,2) NOT NULL DEFAULT 0.0,
    discrimination NUMERIC(4,2) DEFAULT 1.0,
    locale VARCHAR(10) DEFAULT 'en-US',
    stimulus JSONB NOT NULL,
    accepted_answers JSONB,
    cues JSONB DEFAULT '[]',
    media_url TEXT,
    tags TEXT[] DEFAULT '{}',
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMPTZ DEFAULT NOW()

CREATE INDEX idx_exercise_items_domain ON exercise_items(domain_code);
CREATE INDEX idx_exercise_items_difficulty ON exercise_items(difficulty);
CREATE INDEX idx_exercise_items_locale ON exercise_items(locale);

-- 5. Sessions
CREATE TABLE sessions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    patient_id UUID REFERENCES user_profiles(id),
    started_at TIMESTAMPTZ DEFAULT NOW(),
    ended_at TIMESTAMPTZ,
    target_domains TEXT[] DEFAULT '{}',
    target_item_count INT DEFAULT 10,
    device_info JSONB DEFAULT '{}'
);

-- 6. Attempts (core analytics table)
CREATE TABLE attempts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id UUID REFERENCES sessions(id),
    patient_id UUID REFERENCES user_profiles(id),
    exercise_item_id UUID REFERENCES exercise_items(id),
    response JSONB,
    is_correct BOOLEAN,
    partial_score NUMERIC(4,3) DEFAULT 0.0,
    response_time_ms INT,
    hint_count INT DEFAULT 0,
    theta_before NUMERIC(6,3),
    theta_after NUMERIC(6,3),
    created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_attempts_patient ON attempts(patient_id, created_at DESC);
CREATE INDEX idx_attempts_session ON attempts(session_id);

-- 7. Ability estimates
CREATE TABLE ability_estimates (
    patient_id UUID REFERENCES user_profiles(id),
    domain_code VARCHAR(30) REFERENCES domains(code),
    theta NUMERIC(6,3) DEFAULT 0.0,
    standard_error NUMERIC(5,3) DEFAULT 1.0,
    total_attempts INT DEFAULT 0,
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    PRIMARY KEY (patient_id, domain_code)
);

-- 8. Functional milestones
CREATE TABLE functional_landmarks (
    id SERIAL PRIMARY KEY,
    domain_code VARCHAR(30) REFERENCES domains(code),
    landmark_order INT NOT NULL,
    description TEXT NOT NULL,
    theta_threshold NUMERIC(5,2) NOT NULL
);
```

### 1.4 Set Up Row Level Security (RLS)
To make sure patients can only read and write their own data, we will apply Security Policies.
1. Open a new SQL Editor tab (click **+**).
2. Copy and paste the following SQL commands:

```sql
-- Enable Row Level Security (RLS) on all patient tables
ALTER TABLE user_profiles ENABLE ROW LEVEL SECURITY;
ALTER TABLE patient_profiles ENABLE ROW LEVEL SECURITY;
ALTER TABLE sessions ENABLE ROW LEVEL SECURITY;
ALTER TABLE attempts ENABLE ROW LEVEL SECURITY;
ALTER TABLE ability_estimates ENABLE ROW LEVEL SECURITY;
ALTER TABLE patient_achievements ENABLE ROW LEVEL SECURITY;

-- Create Policies to limit access to owner only
CREATE POLICY "Users can only manage their own profile" 
ON user_profiles FOR ALL 
USING (auth.uid() = id);

CREATE POLICY "Patients can only manage their own medical profile" 
ON patient_profiles FOR ALL 
USING (auth.uid() = user_id);

CREATE POLICY "Patients can only view/create their own sessions" 
ON sessions FOR ALL 
USING (auth.uid() = patient_id);

CREATE POLICY "Patients can only manage their own exercise attempts" 
ON attempts FOR ALL 
USING (auth.uid() = patient_id);

CREATE POLICY "Patients can only manage their own ability estimates" 
ON ability_estimates FOR ALL 
USING (auth.uid() = patient_id);

CREATE POLICY "Patients can only manage their own achievements" 
ON patient_achievements FOR ALL 
USING (auth.uid() = patient_id);

-- Enable public reading of static configuration tables (so app can download questions)
ALTER TABLE domains ENABLE ROW LEVEL SECURITY;
ALTER TABLE exercise_items ENABLE ROW LEVEL SECURITY;
ALTER TABLE functional_landmarks ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Allow public read access to domains" 
ON domains FOR SELECT USING (true);

CREATE POLICY "Allow public read access to exercise items" 
ON exercise_items FOR SELECT USING (true);

CREATE POLICY "Allow public read access to functional landmarks" 
ON functional_landmarks FOR SELECT USING (true);
```

3. Click **Run**. Verify that the policies are successfully created.

### 1.5 Auto-Create User Profiles on Signup (Database Trigger)
When users register in Supabase Auth, we want to automatically create a row in the `user_profiles` table so we don't have to manually write sync code.
1. Open a new SQL Editor tab.
2. Paste the following SQL trigger commands:

```sql
-- Trigger function to insert a profile row when a user signs up
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS trigger AS $$
BEGIN
  INSERT INTO public.user_profiles (id, full_name, role)
  VALUES (
    new.id,
    COALESCE(new.raw_user_meta_data->>'full_name', 'New Patient'),
    'patient'
  );
  RETURN new;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

-- Bind trigger function to auth.users table
CREATE OR REPLACE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();
```

3. Click **Run**. This ensures profile synchronization is handled at the database level!

## Step 2: Set Up Firebase (Push Notifications)

Firebase Cloud Messaging (FCM) is used to send daily reminders and motivational notifications to patients. It is completely free.

### 2.1 Create a Firebase Project
1. Go to the [Firebase Console](https://console.firebase.google.com).
2. Click **Create a project** or **Add project**.
3. Name your project: `therapy-nest`.
4. Click **Continue**.
5. Enable Google Analytics (optional, you can toggle it off if you want to keep the configuration simple and local).
6. Click **Continue**.
7. Click **Create project** and wait for it to load, then click **Continue**.

---

### 2.2 Register the Android App
1. In the center of your new project's dashboard home, click the **Android icon** (looks like the Android robot) to add an app.
2. Fill in the registration form:
   - **Android package name:** `com.therapynest.app` *(Must match your Flutter package ID exactly).*
   - **App nickname (optional):** `Therapy Nest Android`
   - **Debug signing certificate SHA-1 (optional):** Leave empty for now (you will generate this when testing locally).
3. Click **Register app**.

---

### 2.3 Download and Save google-services.json
1. In Step 2 of the setup flow, click the **Download google-services.json** button.
2. Save this file to your computer.
3. *Where to put it:* Later when we configure Flutter in Module 0, we will copy this file into the following directory inside your Flutter project:
   `therapy_nest/android/app/google-services.json`
4. Click **Next** on the remaining steps in the Firebase web page and click **Continue to console**.

## Step 3: Set Up Render / Koyeb (Backend Hosting)

Render or Koyeb will host the Python FastAPI backend, which runs the adaptive intelligence scoring engine (IRT) and talks to Supabase.

### 3.1 Sign Up
1. Go to [https://render.com](https://render.com) OR [https://koyeb.com](https://koyeb.com).
2. Click **Get Started** or **Sign In**.
3. Select **Sign up with GitHub**.
4. Authorize Render/Koyeb access.
5. If using Render, the free tier is great for developing but goes to sleep after 15 minutes of inactivity (we can keep it awake using a free service like `cron-job.org` that pings it). If using Koyeb, the free tier runs 24/7.
6. *Note:* You do not need to deploy any code yet. In Module 11, we will configure the Docker files, connect your GitHub repository, and deploy the backend!

## Step 4: Set Up Google Play Console (Developer Account)

Google Play Console lets you distribute the app to actual users. Note that medical/health apps have strict regulations.

### 4.1 Apply for a D-U-N-S Number (Free)
Because Google Play requires an **Organization Developer Account** for apps in the Health/Medical category:
1. Go to the [Dun & Bradstreet registration site](https://www.dnb.com/duns-number/get-a-duns.html).
2. Apply for a free D-U-N-S (Data Universal Numbering System) number for your organization or enterprise.
3. Fill out your details (name of organization, physical address, business type).
4. Wait 1-3 business days. You will receive your D-U-N-S number via email.

### 4.2 Register on Google Play Console
1. Go to [https://play.google.com/console](https://play.google.com/console).
2. Log in with your corporate or developer Google Account.
3. Select **Organization** (not Individual) as your developer account type.
4. Fill in the organization details including name, address, and your D-U-N-S number.
5. Pay the **$25 one-time registration fee**.
6. Submit your identification/verification documents as prompted by Google.
7. *Timeline:* Verification usually takes **3-7 days**. Do this early so it is ready by the time we compile the final app!
