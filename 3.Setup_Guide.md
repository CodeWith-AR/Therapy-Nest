## PHASE D — VOSK SPEECH MODEL (NO TRAINING NEEDED)

### What Vosk Is
Vosk is a **pre-trained offline speech recognition library**. You do NOT need to train or collect speech data for the MVP. It works out of the box.

### Setup Steps
```
1. Add to pubspec.yaml:
   vosk_flutter: ^0.3.3

2. Download model (done automatically in app on first launch):
   Model: vosk-model-small-en-us-0.15
   Size: ~50MB
   URL: https://alphacephei.com/vosk/models
   
3. Store in app documents directory (not assets — too large)
   Path: /data/data/com.therapynest.app/files/vosk-model/

4. The app code in Module 7 handles the download automatically
   with a progress bar shown to the user.
```

### When Would You Need Training?
| Scenario | Needed? | When |
|----------|---------|------|
| Basic English word recognition | ❌ No | MVP — Vosk handles this |
| Aphasia/dysarthric speech | ⚠️ Phase 3 | Only if Vosk accuracy < 60% on real users |
| Urdu/Hindi support | ✅ Different Vosk model | Phase 2 — vosk-model-small-ur |
| Custom medical vocabulary | ⚠️ Phase 3 | Fine-tune only if needed |

**For Phase 3 fine-tuning (not now):**
- Dataset: AphasiaBank (request access at talkbank.org — free for research)
- Tool: Kaldi or fine-tune Vosk with your own recordings
- Requires: IRB approval + 50+ consenting users

### Step 1: Run Schema
```sql
-- In Supabase SQL Editor → paste entire schema from Module 11 of App Prompt

```

### Step 2: Enable Row Level Security
```sql
-- Run after schema creation:
ALTER TABLE user_profiles ENABLE ROW LEVEL SECURITY;
ALTER TABLE patient_profiles ENABLE ROW LEVEL SECURITY;
ALTER TABLE sessions ENABLE ROW LEVEL SECURITY;
ALTER TABLE attempts ENABLE ROW LEVEL SECURITY;
ALTER TABLE ability_estimates ENABLE ROW LEVEL SECURITY;

-- Policy: users can only access own data
CREATE POLICY "own_data" ON user_profiles FOR ALL 
  USING (auth.uid() = id);
CREATE POLICY "own_data" ON patient_profiles FOR ALL 
  USING (auth.uid() = user_id);
CREATE POLICY "own_data" ON sessions FOR ALL 
  USING (auth.uid() = patient_id);
CREATE POLICY "own_data" ON attempts FOR ALL 
  USING (auth.uid() = patient_id);
```

